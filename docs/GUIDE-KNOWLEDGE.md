# 知识库与召回边界

知识库是**旧材料的归档区**，不是写作时自动挂载的记忆。这份文档说清楚：材料怎么进来、怎么拆、什么时候才会影响写作。

## 1. 导入

入口：侧栏「资料 → 导入旧稿」的「归档到书」，或「知识库」页的导入。

- 目录里递归收集 `.md` / `.txt`，原样拷进 `<书>/imports/`。
- 同名同内容跳过；同名不同内容自动加 `-2`、`-3` 后缀，**绝不覆盖**。
- 每次导入写 `imports/INDEX.md`（文件名 + 字数清单），供 AI 通读规划。
- 单次最多 200 篇；超出的会在结果里明确提示，不会静默丢弃。
- 删除记改动日志，可撤销。

`imports/` 是作者原始材料，AI 不删除、不改写。

## 2. 拆分 / 提取

两种粒度：

| 入口 | 做什么 |
|---|---|
| 知识库页「AI 拆分此文档」 | 只处理一篇，按人物/关系/设定/伏笔/大纲拆分 |
| 知识库页「总 Agent 全量提取」 | 通读 `INDEX.md`，分批读全部材料，逐类分派 |

分派去向（全部以**提案**形式进收件箱）：

- 人物档案 → `character` 子 Agent → `propose_character`
- 人物关系 → `relations` 子 Agent → `propose_relations`
- 设定 / 伏笔 / 大纲 → `outline` 子 Agent → `propose_canon` / `propose_clues` / `propose_outline_updates`
- 称谓不统一 → 先 `propose_aliases`，再提关系（否则关系端点挂不上画布）

铁律：只提取不创作；矛盾不上秤（两条都出，注明冲突）；跳过要留痕。

> 极简模式没有子 Agent。知识库按钮仍可用，但任务书要求的分派无法执行；需要分派时切到托管。

## 3. 召回：写作时到底读什么

**结论：写作时不会自动读 `imports/` 原文，也没有自动召回/上下文包。**

一次写作任务实际进模型上下文的是：

1. 任务触发语（章号 / 对象描述）；
2. 技能规程（`skill zhibi-*`）；
3. 模型自己调用的只读工具：
   - `get_chapter`：单章正文，最多 12000 字
   - `get_clues`：全部伏笔台账
   - `get_outline`：故事线/事件 + 最近 12 张档案卡
   - `get_canon`：**前 24 篇**设定，每篇最多 1600 字（不是“全部”）
   - `get_characters`：人物档案，默认 30 人、上限 80 人
   - `get_world_state`：紧凑世界图，事件事实截 80 字
4. 技能里写的“读什么”（例如 `zhibi-draft` 要求先读骨架、人物档案、设定、上一章结尾、伏笔）。

所以：

- 导入材料只有在**提取 → 提案 → 作者采纳**之后，才以台账形式进入写作上下文。
- 未采纳的原始文档，写作时不会自动出现。
- 模型可以自己用文件工具打开 `imports/`，但没有任何任务书要求它这么做；不要依赖这一点。
- 提取轮次与写作共用同一个 DSH 会话，历史里可能残留读过原文的上下文；这是会话历史，不是召回机制。

## 4. 读工具的截断（重要）

| 工具 | 上限 | 说明 |
|---|---|---|
| `get_chapter` | 12000 字 | 超长章会被截断，没有提示 |
| `get_canon` | 24 篇 × 1600 字 | “读取全部设定”是旧描述；实际是前 24 篇 |
| `get_characters` | 默认 30 / 上限 80 | 按目录顺序取，不排序 |
| `get_outline` | 档案卡最近 12 章 | 故事线/事件全量 |
| `get_world_state` | 事件事实 80 字 | 设定只给标题，人物只给别名 |

需要完整内容时，让 AI 直接用文件工具读具体文件；不要假设 `get_*` 返回了全量。

## 5. 常见误解

| 误解 | 事实 |
|---|---|
| 导入后 AI 写作时会自动参考知识库 | 不会；先提取并采纳成台账 |
| `get_canon` 会返回全部设定 | 只返回前 24 篇、每篇 1600 字 |
| 知识库文档删了还能恢复 | 能；改动记录里撤销（当前版本已修好删除撤销） |
| 全量提取会直接改台账 | 不会；全部走提案，作者采纳才落库 |
