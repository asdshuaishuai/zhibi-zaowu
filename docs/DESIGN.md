# 执笔（ZhiBi）3.0 — 跨端超级重构 · UI/UX 与架构设计 v0.1

> **还是执笔**——这是一次彻底的超级大重构，不是新产品。口号升级：**人执笔，AI 研墨**——AI 负责磨墨备纸（搭骨架、理台账、查矛盾、给续写建议），笔永远在作者手里。

技术栈全换：macOS SwiftUI 单端实现 → **DeepSeek Harness（DSH）agent 底座 + GPUI Kit 跨端前端**（macOS / Windows / Linux）。执笔的全部能力 1:1 复刻进新底座，并以**彩云小梦式人机共写**补上「写的时候 AI 就在旁边」这一执笔缺的体验。老项目（zhibi/，SwiftUI）保留不动，数据目录双向兼容。

---

## 1. 产品定位与不变量

| 不变量 | 说明 |
|---|---|
| **人主 AI 辅** | 正文永远作者亲笔；AI 的一切产出（含整章草稿、续写片段）只能以**提案**形态存在，作者采纳前不落盘 |
| **就地反馈** | 凡是在某个窗口/按钮触发的 AI 行为，结果就在那个窗口里过目与采纳，不逼用户绕道收件箱 |
| **全程可视化** | AI 的每一步（准备上下文 → 工具调用 → 结果回灌 → 流式产出 → 完成/失败）在**右侧 Agent 轨迹 Dock** 像对话一样全程可见——这是本作的门户级特性，不是隐藏面板 |
| **跨端一致** | 一套 Rust 代码（GPUI）出 macOS / Windows / Linux；数据目录格式沿用执笔（人随时带走稿子） |

## 2. 技术架构

```
┌────────────────────────────────────────────────────────┐
│                执笔 GPUI 桌面应用（Rust）                 │
│  gpui-kit：Dock / 虚拟列表 / 编辑器 / Markdown 渲染        │
└──────────────┬─────────────────────────────────────────┘
               │ NDJSON JSON-RPC over stdio
               │  ├─ 请求：开 session / 发 prompt / 审批工具
               │  └─ 通知：session.event（全量事件流→轨迹面板）
┌──────────────▼─────────────────────────────────────────┐
│         DSH runtime（`dsh --profile sdk` 子进程）         │
│  Cordis 插件树：模型适配 / 工具注册 / 会话日志 / 审批策略     │
│  ┌─────────────────────────────────────────────────┐   │
│  │  novel-pack（我们的 Cordis 插件包，dsh.bundle）      │   │
│  │  · propose_* 提案工具（复刻执笔 30+ 工具面）          │   │
│  │  · 确定性工具（骨架闸门/连贯性扫描/AI味扫描/对账）      │   │
│  │  · PromptLibrary + 创作法典（13 流派 + 网文/传统两法）  │   │
│  │  · project-store 服务（.zhibi 兼容目录读写）          │   │
│  └─────────────────────────────────────────────────┘   │
└──────────────┬─────────────────────────────────────────┘
               │ OpenAI 兼容 SSE（DeepSeek / GLM / Kimi / Ollama / 局域网端点）
               ▼
                 LLM
```

要点：

- **GPUI 前端不实现 agent 循环**。每次 AI 任务 = 开/复用一个 DSH session，发 prompt，收 `session.event` 流。轨迹面板的数据源就是这条流 + 会话日志（append-only，天然可回放、跨启动保留）。
- **novel-pack 是普通 DSH 插件**（`dsh.bundle` manifest + cordis patch），不 fork DSH 内核；上游更新可跟。
- **提案落盘在宿主侧**：`propose_*` 工具由 novel-pack 落到 `proposals/inbox.json`，GPUI 侧通过工具结果事件 + 文件监视双通道感知。采纳 = 前端点按钮 → 调 novel-pack 的确定性 `apply_*` 工具（幂等保护沿用执笔：同题保护、同 id 合并、快照回滚）。
- **执笔的项目目录格式原样沿用**（`<书名>.zhibi/`：project.json + canon/ + outline.json + clues.json + memory.json + proposals/ + chapters/ch-NNN/）——老用户的项目文件直接打开。


- 左侧导航：**分卷章节树 + 规划台账**（大纲/伏笔/设定/人物/记忆/统计），执笔的信息架构原样保留。
- 中间主区：编辑器或所选台账；顶部一条**全局状态条**（运行中/完成 N 提案/错误 + 停止按钮）。
- 右侧 Dock：**Agent 轨迹**为默认页；**待审提案**为第二页（就地预览 + 一键采纳）；预留**对话**页（自由问答 agent）。Dock 可拖宽、可整体收起（⌘⇧J）。

对应 gpui-kit 组件（执笔 3.0）：`Dock`（右侧停靠 + 拖宽 + 收起）、`Sidebar`（左导航）、`Editor`（正文/代码编辑器组件做稿纸）、`VirtualList`（章节/提案/轨迹列表）、`Markdown` 渲染（预览）、`Table`（时间线/台账）。

## 4. 核心界面详设

### 4.1 写作台（编辑器）——本作的灵魂

稿纸居中（约 720px 栏宽），纸感底色，宋体正文可选。执笔的功能位原样保留：章节状态、字数进度环、快照/回滚、专注模式（⌘⇧F 全窗只剩稿纸）。

**彩云小梦式共写（提案制改造版）**——执笔的「生成后再看」升级为「写时陪伴」：

1. **续写幽灵（Ghost Continuation）**：光标停在段尾 ≥1.2s，自动请求续写 1-2 句，以灰斜体幽灵文本显示在光标后。`Tab` 逐句采纳（采纳的句子转为正文并续请求下一句），`Esc` 拒绝，继续打字即自动作废。幽灵文本**不是正文**，落盘只发生采纳那一刻——提案铁律的最小颗粒度。
2. **分支卡（Three Branches）**：段尾按 `⌘⇧→` 或点「给我几个走向」，AI 一次给 **3 个走向**（各 80-150 字）：走复仇线 / 走师门线 / 走温情线，每张卡片带情绪标签与伏笔影响提示。点选一张 → 该走向展开为完整段落草稿（仍以**草稿提案**形态挂在当前章下方），作者可再改再采纳。`换一批` 重新生成，`全部不要` 关闭。
3. **选区改写菜单**：选中一段 → 浮出菜单：**拉深**（小梦的招牌：同一段写得更细更满）/ **扩写** / **精简** / **换一种写法** / **去AI味改写**。产出以 diff 预览（原文 vs 建议）就地展示，逐条采纳，采纳前自动快照。
4. **分叉点标记**：被分支卡替换或从幽灵文本生长出的段落，左缘留一枚小墨点标记「此段有 AI 参与」，悬停可回看当时的轨迹跳转——共写透明化，正文主权可追溯。

共写请求与重型任务共用同一个轨迹面板（轻量请求标记为「续写」小节点，不淹没主轨迹）。

### 4.2 右侧 Agent 轨迹 Dock

沿用执笔 AgentTrajectoryPanel 的对话式设计并强化：

- 数据源：DSH `session.event` 流（工具调用/结果/文本增量/完成原因全部有事件），按「一次 prompt = 一个会话块」分节。
- 每个块：能力名 + 开始时间；内部气泡：🛠 工具调用（含参数摘要）、↳ 工具结果、💬 流式输出（运行中实时滚动）、✓ 完成（新登记 N 提案）/ ✕ 失败（原因）。
- 点击任何「已登记提案」气泡 → 跳到提案页高亮该提案；点击「写入正文」气泡 → 跳到对应章节位置。**轨迹是可导航的**。
- 顶部过滤：全部 / 仅工具 / 仅文本；运行中顶部有停止按钮。
- 轨迹持久化由 DSH 会话日志承担，重启后可回看。

### 4.3 提案收件箱（Dock 第二页 + 独立台账页）

- 提案卡按 payload 类型渲染（骨架/草稿/伏笔/设定/归类/档案卡/报告…），沿用执笔的视觉语言：标题 + 内容预览 + 采纳/拒绝。
- **就地反馈规则**继续生效：设定归类、整理旧稿、导入后归类等，在触发窗口内直接内嵌结果列表 + 全部采纳；收件箱是留痕与逐条细调的地方，不是唯一入口。
- 批量操作、拒收理由（回灌质量反馈回路）、采纳率统计页保留。

### 4.4 台账页（大纲/时间线、伏笔、设定、人物、记忆、统计）

全部按执笔的信息架构 1:1 复刻，视觉按 GPUI 组件体系重绘：

- **大纲·时间线**：故事线健康度 chips + 双栏时间线表（作者真相｜读者已知）+ 大纲对账条（计划 vs 实际）+ 「AI 建大纲/同步大纲」提案按钮。
- **伏笔台账**：表格（编号/标题/状态/节奏/埋点章/最近动作）+ 健康条 + 「AI 盘点」；埋点修复单条采纳。
- **设定**：左分组树（世界观/势力人物/修炼体系/剧情大纲/题材规则）+ 右 md 编辑；右键：改类别/复制/访达/删除（含确认与 md 同步清理）。
- **记忆中枢**：事实账本 + 矛盾体检 + 人物归一 + 长程档案卡（检索框 + 卡片流）。
- **统计**：每日目标进度环、14 天柱状图、连续天数、AI 采纳率。

### 4.5 书架（首页）

书卡网格（SVG 封面 + 书名 + 字数 + 最近编辑），新建向导（书名/题材 chips/一句话核心 → 自动「搭框架」提案流程），导入向导（oh-story 一等支持；**导入窗内跑完 AI 归类并就地反馈**，执笔已验证的交互直接带过来），选题调研入口。

### 4.6 设置

三分区沿用执笔：通用（目标/主题）、模型服务（预设目录 models.dev + 自定义 OpenAI 兼容端点 + **连通性测试**）、生成与上下文（包预算/自动保存）。DSH 的模型适配插件直接复用，我们的配置面板写 DSH 的 profile 配置。

## 5. 彩云小梦能力拆解 → 执笔 3.0 对应

| 小梦的能力 | 执笔 3.0 的提案制版本 |
|---|---|
| 一键续写（AI 接着写下去） | 续写幽灵（Tab 逐句采纳，Esc 拒绝） |
| 多走向分支供选 | 分支卡三选一（⌘⇧→），选中后展开为草稿提案 |
| 拉深（写得更细） | 选区「拉深」→ diff 预览逐条采纳 |
| 一键成文/扩写 | 选区扩写 / 整章「一键成章」流水线（草稿→审查→去AI味，停在采纳前） |
| 世界书/设定注入 | 创作法典 + ContextPack 造包（预算裁剪，执笔机制原样） |
| 无痕迹生成 | 恰恰相反：分叉点墨点标记 + 轨迹可回溯（我们的差异化卖点） |

## 6. 执笔能力 → DSH 工具面映射（复刻清单）

| 执笔能力 | novel-pack 工具 | 类型 |
|---|---|---|
| 搭骨架 / 闸门评分 | `propose_skeleton` / `gate_skeleton`（确定性） | AI / 本地 |
| 一键成章流水线 | `propose_draft` + `propose_validation` + `propose_deslop` 编排 | AI |
| 分段写作 | 同上，按节拍切块（带上一块实际结尾） | AI |
| 全书连贯性审查 + 埋点修复 | `scan_continuity`（本地 20 类）→ `propose_clue_fixes` | 本地→AI |
| 大纲对账 | `sync_outline_audit`（本地双字组匹配）→ `propose_outline_updates` | 本地→AI |
| 去AI味 25 项 | `scan_ai_tells`（本地）→ `propose_deslop` | 本地→AI |
| 盘点伏笔 / 记一笔 / 档案卡 | `propose_clues` / `propose_memory` / `propose_dossier` | AI |
| 设定归类 / 整理旧稿 / 框架搭建 | `propose_canon_classify` / `propose_canon+clues` / `propose_storylines+events+canon` | AI |
| 一键召回（上下文包） | `build_context_pack`（确定性造包） | 本地 |
| 导入 oh-story / 导出 | `import_workspace` / `export_*` | 本地 |
| 创作法典注入 / 质量反馈回路 | system-prompt 组装插件（PromptLibrary 移植） | 本地 |

提案铁律在 DSH 里落地为：**正文写入工具不存在**；`apply_*` 只由前端在作者点击后调用；工具审批管道（DSH approval）保留为第二道闸。

## 7. 仓库与里程碑

```
zhibi-next/
├── app/          # GPUI 前端（Rust，gpui-kit 0.9）
├── novel-pack/   # DSH Cordis 插件包（TS）：工具面 + prompt + 法典
├── protocol/     # 前端↔novel-pack 的项目数据 API（TS↔RS 类型共享）
└── docs/
```

- **M1 骨架可跑**：GPUI 窗口 + Dock/侧栏布局 + DSH sdk 子进程连通（发一句话收到 session.event 流，右侧轨迹实时滚动）。
- **M2 项目与编辑器**：.zhibi 读写 + 稿纸编辑器 + 章节树/书架。
- **M3 提案闭环**：novel-pack 首批工具（骨架/草稿/盘点）+ 收件箱 + 就地采纳 + 状态条。
- **M4 彩云式共写**：幽灵续写 + 分支卡 + 选区改写（diff 采纳 + 快照）。
- **M5 全能力复刻**：审查/对账/去AI味/记忆/图谱/导入导出/统计。
- **M6 跨端打包**：Win/Linux 适配 + 打包与自动更新。
