# 世界线与剧情预演（作者指南）

世界线不是排期板，也不是画布。它回答：**剧情已经确定到哪一章、之后有哪些 if。**

- 侧栏「世界 → 世界线」：**一条已固化的直线 + 从"现在"扇出的几种未来**。
  左边是正文事实（横轴到固化边界为止），右边是预演（不标章号）。
- 侧栏「世界 → 预言书」：if 线存根，写假设、让 AI 推演、看影响清单。
- 侧栏「世界 → 章节排期」：章 × 幕的工作排期，**与世界线无关**。

## 0. 这张图怎么读（先看这个）

```
─────────────●╮───→ 未来 A（5 节 · 未排章）
  已固化      ╰───→ 未来 B（5 节 · 未排章）
（正文到第 30 章）  "现在"
```

- **左边一根直线**：已写进正文的剧情。它不分支——同一段过去不可能有两种版本。
- **右边的枢轴点**：标注「现在」，就是固化边界那一章。
- **从枢轴散出的每一条虚线**：一条预演（`forecast`），一束一种走向。
- **右半边不标章号**：预演阶段节点**还没有章号**，硬画到某个章号等于编造精度。
  束上的节点按"顺序"排，未排章的显式标成「未排章」（琥珀色）。
- 点一条束（画布上的束名或左栏列表）→ 右侧让出 300px 列出它的**影响清单**
  （改了什么、多严重、为什么）、节点、因果边与操作。画布会按新宽度重排，
  不是被盖住——这一页整幅都是数据，浮层压哪儿都会挡掉东西。

### 束的三条编码（不是装饰）

挑未来时要比的不是名字，是这三样。它们都从台账直接读，鼠标移上去也能在浮层里读到原文：

| 视觉 | 含义 | 数据来源 |
|---|---|---|
| 主线越**粗** | 这一章事件越多（戏肉 / 过渡，一眼分得出） | `events.json` 按章计数 |
| 主线上的**每个点** | 一个真实事件（实心=已发生） | `events.json` |
| 束越**长** | 预测推到第几章 | 束上最后一个节点的章号 |
| 束上的**一串点** | 这条未来的多个关键关节（不是只给一个落点） | 预演节点，按序 |
| 空心点 | **推演章序**：从边界之后逐章推算，未定稿 | `Beat::scheduled = false` |
| 端点越**大** | 波及越广（人物 + 线索 + 设定） | 推演结果里的 `derived` 三张清单 |

预演不可能有真章号（正文还没写到那儿），但"第 31 章会发生什么、第 32 章
会发生什么"正是作者要的粒度。所以：**没排章的节点按边界之后逐章推进，
标成「演31」这样的推演序**，图例和面板都写清楚它是推演，不是排期。

推演区在时间轴上是**横向放大**的（主干的比例尺不变，刻度仍对得上正文）。
不放大时 5 个节点只占 100px，糊成一团；放大后一段预测才读得清。
画布拖拽是手型光标（按住变握拳），滚轮缩放，和别的图谱页一致。

枢轴上的「现在 · 第 N 章 · 欠 M 笔」：M = 还没兑现的伏笔数。
**选路之前先看这个**——一条未来好不好，很大程度取决于它能不能把这些账收掉。

## 0.1 三条铁律（必读）

1. **已经固化的剧情只有一条线**——就是正典，由**正文**决定。
2. **if 线永远不会被扶正**。没有「扶正」这个动作，接口层面也不存在（见 `Store::fix_line`）。
3. **预言书与主线无关**。它记录的是 if 分支，不进主线、不影响主线，是给作者以后
   写番外时取用的存根。

之所以反复写这三条：早期版本里「推演一条线 → 扶正 → 时间轴多出一段实线」是存在的，
那会让"预演一下"看起来像"剧情定了"。这是设计里最容易被再次做错的一处。

## 0.2 点选、抽屉与反馈（交互）

- **点束上的一个关节点**（空心 / 实心圆点）→ 底部弹出**节点抽屉**：它属于哪条线、
  第几章（或推演序）、备注、上下游因果链（← 上游 / → 下游，含明暗），以及操作：
  - 「落实为第 N 章」/「章号＋1」：给推演节点定一个章号（写回 `chapter`）。
  - 「采纳进正典」：**只有已排章且未进正典的节点才出现**；没排章时显示琥珀提示
    「先给它定第几章，才能采纳」。点它走 §5.3 的两步采纳。
  - 「从这儿推演」「关联画布」「删节点」。
- **点主线上的一个事件点** → 底部弹出**事件抽屉**：列出该章台账事件
  （编号 / 客观事实 / 已发生还是计划 / 读者已知还是未揭示）。它是**只读**的——
  正典事实来自事件台账，要改去大纲 / 章节排期页，抽屉里也写明这一点。
- 点节点会**同时选中它所在的线**：右侧详情面板列出影响清单、全部节点与因果边
  （不截断，面板自己滚动），左栏列表高亮，预言书也联动选中同一条线。
  对比页里点泳道同样切换左线并联动预言书。
- **操作反馈条**在页眉下方：成功绿、失败 / 拒绝琥珀，右侧「×」可关闭。
  所有写操作（改章、采纳、删节点、关联画布、标边界……）的结果都落在这里，
  不会静默无动作。这条配色规则全应用共用（`theme::feedback_is_error`）。
- 画布底部有**章号刻度尺**（步长随跨度自适应），只标到固化边界为止；
  滚轮缩放、按住拖拽平移，「◀ ▶」回全览 / 定位选中线。

## 1. 四个概念

| 概念 | 含义 |
|---|---|
| **正典（唯一）** | 已经写进正文的那条线，是事实基准。`worldlines.json` 里的 α。 |
| **预演线** | `forecast` = 从固化点往后推"接下来会怎样"；`what-if` = 改过去看"如果那样会怎样"。两者都只是预演。 |
| **固化边界** | 剧情确定到第几章。**只由两个来源取大**：① 有正文的最大章号；② 作者在世界线页手标的「已定剧情到第 N 章」（`worldline.json` 的 `confirmedThrough`）。**预演线的节点不参与**。 |
| **if 存根** | 预言书里的每一条预演线。永久保留，可归档、可删除，但不会成为正典。 |

## 2. 怎么标边界

**正常情况什么都不用做**：正文写到第几章，边界就是第几章。

只有一种例外——**章目/细纲已经定了、正文还没写**。这时在世界线页顶部填
「已定剧情到第 N 章」再点「确认」。它会和正文取较大值；正文写到更后面时自动跟上，
无需再改。清空输入框点「确认」即回到纯按正文判断。

输入框只接受正整数章号：填了非数字（如字母）点「确认」会收到琥珀色错误提示，
**不会**把边界悄悄清掉；只有留空点「确认」才是清掉手标边界。

## 3. 开一条预演线

1. 世界线页选中一条线（或某个节点），点「从此处再分叉」；预言书页也可以直接「假设推演」。
2. **宿主先建线**：`fork_at_chapter` 写入 `parentId`、`forkNode`、`forkedChapter`。
3. AI 收到任务后只负责 `simulate_worldline` 填节点/边/影响，**不要再调 `propose_worldline`
   开第二条线**。
4. 只有宿主没能建线（例如世界线文件为空）时，AI 才会自己开一条无血缘的线；这是例外，
   不是默认路径。

预测续写（forecast）时宿主不预建线，AI 用 `propose_worldline(kind=forecast)` 开线，
fork 章默认取最新成稿下一章，然后 `simulate_worldline` 写入推演结果。

## 4. 看推演结果

- **节点**：第几章发生什么，`state` 为 `planned|adopted|written|branch-only`。
- **边**：因果/埋设/回收/卷入/冲突/暗线。
- **影响清单 diffs**：这条假设对正典的影响，每条写「目标 / 原状 / 新状态 / 为什么」。

影响清单本身不是正典。它回答的是"如果真这么写，会牵动哪些设定"。

## 5. 预演怎么变成正典

**只有一条路：写进正文。**

- 想采纳某个预演节点 → 把它写成正文，或者先晋升成一张计划事件提案、采纳后进
  `events.json` 作为待写计划。计划事件不会改变固化边界——边界跟着正文走。
- 整条线**没有**"一键扶正"。这条线会一直留在预言书里当 if 存根，供以后写番外时翻。

### 5.1 逐条晋升影响（promote_diff）

预言书右列影响清单，每条点「晋升」：

- 设定新增 → `propose_canon`；设定修订 → `propose_canonRevise`（采纳前自动备份原文）
- 伏笔 → `propose_clues`；人物 → `propose_aliases`；事件/故事线 → `propose_outlineUpdates`

生成的是**提案**，还要去收件箱采纳。采纳时才写 `promoted`；拒收后可以再次晋升。

### 5.2 按章晋升（promote_diff_chapter）

事件类影响可以指定章号，生成 `plannedEvent` 提案（`happened=false`），采纳后进
`events.json`，在排期板/画布上显示为计划事件。

### 5.3 逐节点采纳（adopt_node）

时间轴上点一个计划节点 → 抽屉里「采纳进正典」（没排章的节点先「落实为第 N 章」，
否则按钮不出现、只给琥珀提示）：

1. 生成 `plannedEvent` 提案，节点状态**此时仍是** `planned`。
2. 去收件箱**再采纳一次**，才写 `events.json`，节点转 `adopted`。
3. 正文写到该章时，所有 `adopted` 且章号 ≤ 最新成稿章的节点自动转 `written`。

> 关键：逐节点采纳是**两步**。只点时间轴上的「采纳」不会进正典；收件箱那一票才算。

## 6. 老数据：旧版的「已扶正」线

早期版本写入 `kind: "fixed"` 的线，现在读进来一律降级成**普通预演线**：

- 它不再算作"已定剧情"，不参与固化边界；
- 它是 `fixedThrough` 字段也不会再顶高边界（字段仅为兼容保留，不参与计算）；
- 它会回到预言书里当 if 存根，或者在世界线页当预测线查看。

如果那段时间的剧情确实已经定了，正确做法是把它写进正文，或手标「已定剧情到第 N 章」。

## 7. 常见卡点

| 现象 | 原因 | 处理 |
|---|---|---|
| 推演到很后面，边界却没动 | **这是对的**：边界只看正文与手标 | 想让边界过去，去写正文或手标边界 |
| 想"采纳整条线"找不到按钮 | 已移除：机制上不存在扶正 | 写进正文；或逐条晋升影响进收件箱 |
| 开了假设线却多出一条无血缘线 | AI 照旧版技能又调了 `propose_worldline` | 删掉多余的线；当前技能已改为"宿主已开线，直接 simulate" |
| 逐节点采纳后正典没变 | 只完成了第一步 | 去收件箱再采纳 `plannedEvent` 提案 |
| 时间轴边界比正文靠后 | 手标了「已定剧情到第 N 章」 | 清空该输入框点「确认」即回落 |
