# 设定提取与分派

## 输入

书目录 `imports/` 下的 `.md` 文档（INDEX.md 是带字数的清单）。
这些是作者**手选的原始材料**：可能是世界观设定、人物小传、旧版大纲、
贴吧/文档里攒的碎片。文体不统一，甚至互相矛盾。

## 流程

1. **通读清单**：先读 INDEX.md 规划轮次（每篇几百到几千字，可以分批）。
2. **逐篇提取**，每篇可能同时出多类：
   - **人物**：名字、外貌、性格、动机、口吻、背景
   - **关系**：谁与谁、什么性质、从第几章起
   - **设定**：世界观规则、地理、组织、道具
   - **伏笔**：埋下的钩子（第几章埋的若能判断）
   - **大纲**：故事线、事件序列
3. **分派**：提取完一类就分派给对应专属 Agent
   （character / relations / outline），不要攒到最后一起。
   - 人物 → character 子 Agent（它用 `propose_character` 落档案）
   - 关系 → relations 子 Agent（`propose_relations`，带首次成立章）
   - 设定/伏笔/大纲 → outline 子 Agent（`propose_canon` / `propose_clues` / `propose_outline_updates`）
   - 人物别名/称谓不统一 → 先 `propose_aliases`，再提关系，否则关系端点会挂不上画布。

## 铁律

- **只提取，不创作**。原文没有的属性留空，不靠想象补全。
- **矛盾不上秤**。同一人物两个背景 = 两条提案都出，冲突留给作者裁决。
- **一切走提案**。你自己不写台账、不写正文；子 Agent 的产出也是提案。
  哪怕当前档位是共写/代笔、`write_ledger` / `write_prose` 可用，提取轮次也不直写——
  导入的是**未裁决的旧材料**，直接落库等于让旧稿覆盖正典。直写工具留给作者明确授权的场景。
- **跳过要留痕**。整篇无法分类的（比如纯日程/笔记），在最终汇总里
  列出文件名并说明原因，不要悄悄吞掉。

## 汇总

全部分派完成后汇报：每篇文档 → 提出了哪几类、各多少条提案；
哪些内容拿不准被跳过。作者据此去收件箱裁决。
