# 搭骨架

先读，再搭。跳过阅读直接产节拍，得到的一定是通用套话。

## 读什么

1. **上一章结尾**（`chapters/ch-<N-1>/prose.md` 末尾 1500 字）：语气、在场人物、悬着的那口气。
2. **伏笔台账**（`get_clues`）：`plantedChapter` 到期的、`status` 未兑现的。
3. **大纲与事件**（`get_outline`）：本章在故事线上的位置，哪些事件标了本章。
4. **人物档案**（`get_characters`）：本章要出场的人此刻的动机与状态。

## 产什么

4-6 个节拍。每个节拍只写四件事：

- **一句话动作**：谁做了什么，产生了什么不可逆的后果。
- **建议字数**：全章合计要贴近本书的 `chapterWordTarget`。
- **场景层**：视角人物 / 地点 / 在场其他人。
- **章尾钩子形态**：悬念、反转、情绪落点，三选一，说清是哪一种。

## 期待感管理

- 每章至少推进一条故事线，且**状态要变**（推进/受阻/反转），不能"又提了一次"。
- 到期伏笔必须进合同：本章要么收，要么明确往后推并说明理由。
- 骨架里不写正文句子。骨架是结构，正文是血肉，混在一起作者没法改结构。

## 落库

用 `propose_skeleton` 提案。结语一句话说明本章的期待感设计（读者为什么要往下翻）。

提案须给出依据来源（引用既有伏笔/设定/事实编号）。
