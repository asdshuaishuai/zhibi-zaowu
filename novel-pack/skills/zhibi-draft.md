# 写草稿

## 前提

只对**已批准**的骨架动笔。骨架未批准就写，写出来的东西作者大概率推翻，白花一次上下文。

## 读什么（不读不写）

1. **本章骨架**：`chapters/ch-NNN/meta.json` 的 `beats` 与 `skeletonApproved`。`skeletonApproved` 不为 true 就停下，先让作者批准。
2. **人物档案**：`get_characters` 取出场人物的 `voice`（句长、用词、口头禅）、`motivation`、`status`；锁定的字段不要绕开。
3. **设定**：`get_canon` 里与本章地点/势力/规则相关的条目。设定没写到的，不要自造。
4. **上一章结尾**：`chapters/ch-<N-1>/prose.md` 末尾 1500 字——接住那口气。
5. **伏笔**：`get_clues` 里 `plantedChapter` 到本章、`status` 未兑现的。
6. **记忆召回 + 冲突复核**（`recall_memory` + `infer_memory`）：以出场人物为 `terms` 各调一次
   `recall_memory`（`chapter`=本章——锚"正在写的这一章"，不是上一章），核对当前章的关系状态与前情事件；
   再调一次 `infer_memory`，看有没有未消化冲突或陈旧事实与出场人物有关。
   - 出场人物在当前章的关系（师徒/仇敌/夫妻…）与召回事实不一致时，**在草稿结语里点出来**，不要让正文带着错关系往前写。
   - 某条关键事实被标陈旧（>30 章没复核）但本章剧情用到了它，在提案 `note` 里请作者复核是否需更新其 `fromChapter`。
   - 骨架批准的节拍若与召回内容矛盾，**停下来问作者**，不要替作者改骨架。
6. **记忆召回 + 冲突复核**（`recall_memory` + `infer_memory`）：以本章出场人物为 `terms`
   各调一次 `recall_memory`（`chapter`=本章），核对「他们此刻的关系状态」与「前情里发生过的关键事件」；
   再调一次 `infer_memory`，看有没有未消化的单值冲突或已被标陈旧的非耐久事实与出场人物有关。
   - 若出场人物在当前章的关系区间（师徒/仇敌/夫妻…）与召回事实不一致，**在草稿结语里点出来**，不要让正文带着错关系往前写。
   - 若某条关键事实（如「沈砚获得断刀」）被标了陈旧（>30 章没复核），但本章剧情其实用到了它，在提案 `note` 里说明"本章实际引用了事实 F-xxx，请作者复核是否需更新其 `fromChapter`"。
   - 调用不需要复述给作者，但**骨架批准的节拍若与召回内容矛盾**，先停下来问作者，不要替作者改骨架。

## 怎么写

- 按节拍顺序走，一拍一段落群，不要打乱。节拍之间的过渡用动作或对话接，不要用"然后""接着"。
- 视角锁死在骨架指定的视角人物上。他看不见的，不写；他不知道的，不写成他知道。
- 在场人物说话要能听出是谁：口吻来自人物档案的 `voice` 字段，不是通用文雅腔。
- 章尾落在钩子上，落在骨架指定的那个形态。

## 风格透镜（作者可点名，默认贴本书既有文风）

吸收真实作家/编剧的**方法**而非抄其文字。作者点名某透镜时按它调整句法与节奏；
没点名就延续上一章结尾的文风，不要突然换腔。

- **白描克制**（汪曾祺/阿城式）：短句、少形容词、靠动作与物件传情，情绪藏在留白。
- **文青抒情**（猫腻/烽火式）：长短句交错、意象与议论穿插、权谋里夹人生感慨；
  抒情不超过段落三分之一，否则拖节奏。
- **爽文直给**（番茄/起点升级流式）：目标-受阻-打脸-收获四拍快切，数值/地位变化
  写明白，少内心独白，章尾必留钩子。
- **悬疑冷峻**（紫金陈/东野圭吾式）：信息差驱动，视角只给读者该知道的，细节伏笔
  前置，反转靠回收而非新信息。
- **历史厚重**（马伯庸/刘和平式）：考据细节落地（官制/器物/礼仪），台词带潜台词
  与身份差，大事件用小人物视角切。
- **群像口语**（兰晓龙式）：每人一句口头禅/句癖区分声口，对话推进而非叙述推进，
  悲喜用克制反差顶出来。

编剧侧同理：场景先写"谁想要什么、被什么挡、转折后价值翻到哪面"，再填台词；
台词潜台词 > 直白说明（刘和平式），群像靠声口不靠标签（兰晓龙式）。

## 不许做

- 不许替作者改骨架。骨架有问题就在结语里说，不要偷偷改结构。
- 不许写"（此处可展开）""……"这类占位。
- 不许把台账里的设定当成正文解释给读者听。设定是背景，不是台词。

## 落库

用 `propose_draft` 提案。采纳前不落盘——正文只能由作者按"采纳"落笔。

提案须给出依据来源（引用既有伏笔/设定/事实编号）。
