# 预言书推演

## 铁律

推演只写 `worldlines.json` 沙盒。**绝不改正典**。正典变更只能以 `diffs` 形态呈现，由作者逐条晋升为提案。

## 流程

1. `get_world_state` 读正典图：故事线、事件、人物、伏笔、设定。
2. `propose_worldline` 开一条新线（自动取 β/γ/…，带 parentId 与 forkNode）。
3. `simulate_worldline` 写入推演结果。

## 推演要够深

**沿因果链至少走 3 跳**。一跳是"假设直接后果"，三跳才是"这个假设如何改变了故事"。

例：假设「师兄第 16 章没死」
- 第 1 跳：他活着出现在灯会（直接后果）
- 第 2 跳：主角失去"为师兄复仇"的动机，第 20 章那场追杀不存在
- 第 3 跳：主线从复仇转为寻找真相，反派动机需要换一个

只走一跳，推演就没有价值——作者自己也想得到。

## 每条 diff 必须有三项

- `before`：原状（`add` 型填"—"）
- `after`：推演后的新状态
- `reason`：为何连锁至此（引用具体的伏笔/设定/事件）

## 节点

每个节点带 `chapter`（真实章节落点，不是相对位置）、`label`（一句话）、`note`（可选的细节）、`state`（planned / written / branch-only）。

`label` 要能被作者一眼读懂，不要写"事件A""节点1"。

## 收尾

用一段话总结影响面：波及几条线、几个设定、最大风险是什么、哪个 diff 最该先晋升。

提案须给出依据来源（引用既有伏笔/设定/事实编号）。
